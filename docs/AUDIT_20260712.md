## 2. Lo Bueno

### Arquitectura
- **Separación limpia**: API routers (`backend/api/`), servicios (`backend/services/`), scan modules (`backend/scan/`), y núcleo (`backend/*.py`). Cada capa tiene responsabilidad clara.
- **Multi-vault**: Registry en `~/.hermes/lgb/vaults.json` con switch en caliente. DB por vault (`{vault}/.lgb/library.db`). Bien pensado.
- **MCP server**: 20+ tools expuestas a agentes (overview, search, explore, neighbors, import_arxiv, import_github, create_note, publish_lens, etc.). 1,063 líneas, bien documentado en AGENTS.md.
- **Watchdog SSE**: Eventos filesystem en tiempo real via watchdog → SSE → frontend. Auto-rescan al detectar cambios.
- **WSL-aware**: Path validation, browse roots con /mnt/c, proxy fallback en API client. Maneja correctamente el 9p filesystem.
- **Security middleware**: API key opcional, rate limiting, path validation contra workspace root. Production mode que oculta errores.

### Frontend
- **3D engine maduro**: Graph3DEngine (693 líneas) con LOD, particle manager, constellation figures, starfield, GPU cache, layout modes. Bien modularizado.
- **UI rica**: Menu bar con dropdowns, detail panel con metadata/neighbors/preview/notes, search con 3 modos (text/related/hub), minimapa, context menu, quick access, agent lens bar, folder picker, tooltip, activity log.
- **API client con fallback**: Si el proxy Vite falla, intenta directo a :3001. Maneja 502/503/504.
- **Notas inline + vault**: Sistema de notas ancladas a nodos, con storage inline (bloque en .md) o vault (_notes/). Labels, búsqueda, edición.

### Testing
- 22 archivos de test cubren: graph engine, pipeline, scan, imports, notes, vaults, browse, MCP, constellation, impact, karpathy, inline notes, workspace watcher.
- CI en GitHub Actions: ruff + pytest + typecheck + build.
- conftest.py con fixtures compartidas.

### DevOps
- Docker compose con backend + frontend.
- Dependabot configurado para pip, npm, y github-actions.
- .gitignore completo.
- Scripts de health y check-connect.

## 4. Lo Mejorable (deuda técnica)

### TECH-1: Type safety (34 mypy errors en 12 archivos)
| Archivo | Errores | Issue principal |
|---------|---------|-----------------|
| `imports.py` | 10 | `str | None` sin guard antes de `.strip()`, confusión de tipos XML |
| `library_bridge.py` | 6 | `Queue[Any] | None` sin guard de None |
| `services/graph_pipeline.py` | 4 | Dict value types `Any | None` vs `int` |
| `scan/karpathy.py` | 3 | Return type mismatch |
| `overview.py` | 3 | `str` asignado a `Path` |
| `graph_engine.py` | 2 | `None` asignado a `dict[str, float]` |
| `scan/walker.py` | 2 | position arg type demasiado amplio |
| Otros | 4 | Varios |

**Impacto:** No bloquea runtime (Python ignora tipos), pero degrada IDE support y refactor safety. Algunos podrían ser `AttributeError` en paths de None.

### TECH-2: Format drift (44 archivos)
`ruff format --check` reporta 44 archivos que reformatearía. Puro style drift.

**Acción:** Un commit `chore: ruff format backend/` lo resuelve.

### TECH-3: Seguridad XML parsing (5 Medium)
`imports.py` parsea feeds XML de arXiv/PubMed/DOI con `xml.etree.ElementTree` — vector XXE/Billion Laughs. `defusedxml` está en requirements.txt pero NO se usa en imports.py.

**Acción:** Reemplazar `xml.etree.ElementTree` con `defusedxml.ElementTree` en imports.py.

### TECH-4: URL scheme audit (Medium)
`imports.py:31` usa `urlopen` sin validar scheme — podría seguir redirects a `file://` (SSRF).

**Acción:** Validar que URL sea `http://` o `https://` antes de `urlopen`.

### TECH-5: God files
| Archivo | Líneas | Issue |
|---------|--------|-------|
| `mcp_server.py` | 1,063 | Todas las tools MCP en un solo archivo |
| `menuBar.ts` | 940 | Toda la lógica de menú + modales en uno |
| `detailPanel.ts` | 738 | Panel + notas + preview + constellation en uno |
| `imports.py` | 744 | Todos los importers en uno |
| `Graph3DEngine.ts` | 693 | Renderer + layout + camera en uno |

**Acción:** Refactor incremental, no urgente pero reduciría merge conflicts.

### TECH-6: Frontend chunk size
- `es-CUtCD1Bx.js` 914 kB
- `forcegraph-BtaZ82qX.js` 1.3 MB
Vite warning: chunks > 500 kB. 3d-force-graph y three.js son pesados.

**Acción:** Code-splitting de highlight.js (ya es lazy-loaded), dynamic import de three.js examples.

### TECH-7: MCP y Bridge sin memoria compartida
Dos procesos separados con su propia copia del grafo en RAM. Mutaciones por MCP requieren `rescan()` manual en Bridge y viceversa.

**Acción:** Documentado en AGENTS.md. Solución real: shared memory o pub/sub entre procesos.

### TECH-8: 6 Dependabot PRs sin merge
- `dompurify-3.4.8`, `marked-18.0.5`, `vite-8.0.16` (frontend)
- `fastapi-gte-0.136.3`, `mcp-gte-1.27.1`, `pydantic-gte-2.13.4` (backend)

**Acción:** Reviewar y mergear.

### TECH-9: No frontend tests
No hay tests de frontend. Solo typecheck y build en CI.

**Acción:** Agregar Vitest con smoke tests mínimos (render AppController, click menu, search).

### TECH-10: Watchdog thread leak (test warning)
`RuntimeError: Event loop is closed` tras pytest teardown. Observer thread sobrevive al loop.

**Acción:** Guard en `stop_watcher()` con `loop.is_closed()` check.
